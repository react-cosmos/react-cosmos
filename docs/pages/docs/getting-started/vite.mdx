# Vite

This is a guide for setting up React Cosmos in a Vite project.

## Getting Started

<details>
  <summary>Do you already have Vite installed?</summary>

If you're starting from scratch, follow [this guide](https://vitejs.dev/guide/#scaffolding-your-first-vite-project) to get started with Vite with React. At a minimum you'll need the `index.html` and `main.jsx` root files and `@vitejs/plugin-react` installed.

</details>

Install the required packages:

```bash npm2yarn
npm i -D react-cosmos react-cosmos-plugin-vite
```

Create `cosmos.config.json` and enable the Vite plugin:

```json filename="cosmos.config.json"
{
  "plugins": ["react-cosmos-plugin-vite"]
}
```

Add `cosmos` and `cosmos-export` scripts to package.json:

```json filename="package.json"
"scripts": {
  "cosmos": "cosmos",
  "cosmos-export": "cosmos-export"
}
```

Create a basic fixture at `src/Hello.fixture.jsx`:

```jsx filename="src/Hello.fixture.jsx"
export default <h1>Hello World!</h1>;
```

Start React Cosmos:

```bash npm2yarn
npm run cosmos
```

🚀 Open **[localhost:5000](http://localhost:5000)** in your browser.

The `Hello` fixture will show up in your Cosmos UI and will render when you select it.

**Congratulations 😎**

You've taken the first step towards designing reusable components. You're ready to prototype, test and interate on components in isolation.

## Vite Config

Cosmos generates a default Vite config if a custom one isn't provided.

### Custom Vite Config

Cosmos picks up `vite.config.js` from the project root automatically. Use the `vite.configPath` setting to provide an existing Vite config at a different path:

```json filename="cosmos.config.json"
{
  "vite": {
    "configPath": "./tools/vite.config.js"
  }
}
```

## Configuration

Vite-related settings you can optionally customize in your Cosmos config:

| Option               | Description                                                                    | Default                                  |
| -------------------- | ------------------------------------------------------------------------------ | ---------------------------------------- |
| `vite.configPath`    | Path to Vite config. Set to false to disable reading it from the default path. | `"vite.config.js"` or `"vite.config.ts"` |
| `vite.mainScriptUrl` | URL to custom main script (eg. `"/src/my-main.tsx"`).                          | Detect main script URL.                  |
| `vite.port`          | Run the renderer on its own port. See [Renderer URL](#renderer-url).           | None (uses the Cosmos port).             |

## Renderer URL

The Cosmos renderer is served by the Cosmos dev server at `/renderer.html`, next to the Cosmos UI. Vite runs as part of the Cosmos server, including its hot reloading connection, so a single port is all you need. Any number of Cosmos instances can run side by side without sharing anything.

The renderer's HTML is your project's `index.html`, same as in a static export. Vite's `server.proxy`, `server.allowedHosts`, `server.cors`, `server.fs` and `publicDir` options apply to the renderer as usual, while Vite's `server.port`, `server.strictPort`, `server.host`, `server.https` and `server.open` options don't, because the Cosmos server is the one listening. Use the `port`, `host` and `https` options from your Cosmos config instead.

### Separate renderer port

Because they share an origin, the renderer and the Cosmos UI also share cookies and local storage, and your fixtures see `/renderer.html` as the URL path. If your code needs an origin of its own (eg. it registers a service worker or it reads the URL path), set `vite.port` to run the renderer on a separate Vite server:

```json filename="cosmos.config.json"
{
  "vite": {
    "port": 5050
  }
}
```

The renderer port is exact. Cosmos fails to start if the port is taken, because the Cosmos UI can't follow the renderer to another port.
